## 中转站相关

### 1. Anthropic 兼容站不都认 `x-api-key`

**报错：**

```
HTTP 401 {"code":401,"message":"token is required"}
```

**原因：** 大多数 Anthropic 兼容站（Claude 官方、大部分第三方）用 `x-api-key` 头传密钥。但 **MiniMax Code 网关**这类只认 `Authorization: Bearer`。用 `x-api-key` 发过去，网关根本读不到密钥，于是报「token is required」。

**解法：** 给供应商加 `authStyle` 字段：

```jsonc
{ "api": "anthropic", "authStyle": "bearer" }
```

代码里对应：

```js
function authHeaders(p) {
  if (p.authStyle === 'bearer') {
    return { 'Authorization': `Bearer ${p.key}` };
  }
  return p.api === 'anthropic'
    ? { 'x-api-key': p.key, 'anthropic-version': '2023-06-01' }
    : { 'Authorization': `Bearer ${p.key}` };
}
```

**教训：** 看到「token is required」先怀疑自己的传参位置，别急着说对方 API 有 bug。

### 2. 域名解析到 `0.0.0.1` 说明被墙了，不是 DNS 配错

**现象：**

```bash
$ nslookup api.workbuddy.ai
api.workbuddy.ai canonical name = ...
Address: 0.0.0.1        # ← 这个
```

**原因：** 部分服务商对特定地区/客户端做了污染，把域名解析到 `0.0.0.1`（黑洞地址）。这不是 DNS 配置错误，是上游故意让你连不上。

**解法：** 换站点域名。比如 `api.workbuddy.ai` 被污染，但 `www.workbuddy.ai` 正常。

**排查顺序：** 本机 DNS → 网关 DNS → 权威 DNS，三方对比。如果权威返回正常但本机返回 `0.0.0.1`，就是被污染了。

### 3. 流式响应里 `finish_reason` 要等最后一个 chunk

**症状：** 前端显示回复已结束，但内容少了一截。

**原因：** Anthropic 的流式事件里，`message_delta` 才带 `stop_reason`；OpenAI 的 `finish_reason` 在最后一个 `chunk.choices[0]` 里。如果转换时提前收尾，最后几个 token 会丢。

**解法：** 转换层要记住「已经收到 deltas 但还没收到结束事件」，只在真正收到 `message_stop` 时才发 `[DONE]`。

## 内存与资源相关

### 4. 2G 内存跑 QQ 机器人是极限，swap 会长期占用

**实测数据：**

```
MemTotal    1737 MB
MemFree       82 MB        ← 几乎没剩
MemAvailable 656 MB        ← 真实可用
SwapUsed    1715 MB        ← 已经吃掉 42%
```

**能跑，但代价是：** 大量热数据被换到 swap，磁盘 IO 会周期性飙高。PSI 内存压力 `some avg10=0.66%` 说明还没到 thrash 的程度，但余量很小。

**如果要加功能（比如再加个微信协议端），先做这两件事：**

```bash
# 关掉云主机上完全用不到的服务
systemctl disable --now fwupd multipathd    # 固件更新 + 多路径存储
systemctl disable --now snapd               # 如果没装 snap 包

# 清掉不再使用的 Docker 镜像
docker image prune -a
```

**建议：** 想跑得舒服，4G 内存起步。

---

### 5. 容器不设内存上限，OOM 会杀整个系统

`docker run` 默认 `Memory=0`，也就是**不限制**。不加限制的话，某个容器内存爆炸时，Linux 的 OOM killer 会在**整台机器**范围内挑受害者 —— 完全可能干掉你的 SSH 和 Docker daemon。

**建议给关键容器设上限：**

```bash
docker update --memory 800m --memory-swap 1200m astrbot
docker update --memory 900m --memory-swap 1400m snowluma
```

### 6. 临时文件会无声地吃掉几个 G

**现象：** 磁盘莫名其妙少了 800MB。

**原因：** 机器人框架会把收到的每张图片、每段语音都存到 `data/temp/`，**从不自动清理**。跑了几天，1700 多个文件堆在里面。

**解法：** 加个定时清理，只留最近 1 小时：

```bash
#!/bin/bash
find /path/to/astrbot/data/temp -type f -mmin +60 -delete
```

如果服务器上没有 systemd timer，加进 crontab：

```cron
0 * * * * /path/to/clean_temp.sh
```

## 备份相关

### 7. 备份包必须把代码和密钥分开

**为什么：** 如果备份仓库（哪怕是私有的）哪天泄露，或者你不小心把它设成了 public，那所有 API key 就一起没了。

**做法：**

```
backup.tar.gz
├── code/          # 代码，泄露了无所谓
└── secrets/       # 密钥，泄露了要命
    ├── relay.json
    ├── minimax-accounts.json
    └── redacted/          # ← 这一份是脱敏的
        └── relay.example.json   # 全是 REPLACE_ME
```

恢复时用 `secrets/` 里的真实文件；对外分享时只给 `secrets/redacted/`。

---

### 8. GitHub Contents API 大文件要分块，且 100MB 是硬上限

用 Contents API 上传单个文件，超过 **100MB** 直接 422。备份包如果压不进 100MB，要么改用 Git LFS，要么拆包。

另外 API 是**幂等覆盖**的：同一个路径重复 PUT 需要带上 `sha`（先 GET 拿），否则会 409。

## 协议端相关

### 9. Poke（戳一戳）在群里发不出去

**报错：**

```
retcode=1400 message element "poke" can only be sent in a direct private chat
```

**原因：** OneBot 协议明确限制，`poke` 消息段**只能在私聊里发**。群里发会被网关拒绝。

**解法：** 判断消息类型，群里只能回文字，私聊才能回戳：

```python
if event.message_obj.type == "private":
    await event.send(MessageChain([Poke(user_id)]))
else:
    await event.send(MessageChain([Plain("别戳啦！")]))
```

---

### 10. 无文本事件不能靠 `is_wake` 触发回复

**症状：** 被戳了没反应。

**原因：** Poke 事件没有文本内容，框架的唤醒逻辑走的是文本匹配，`event.is_wake = True` 这种赋值式触发**不生效**。

**解法：** 直接调 provider 拿回复，再手动发：

```python
resp = await self.context.get_using_provider().text_chat(
    prompt="用户戳了你一下",
    session_id=event.session_id,
)
await event.send(MessageChain([Plain(resp.completion_text)]))
```

### 11. 插件页面的 token 是跟「页面名」绑定的

**报错：** 从插件页 A 跳到插件页 B，提示 `Token 无效`。

**原因：** AstrBot 给插件页面签的 token 里 **pin 了 `page_name`**。你用 A 页面的 token 去访问 B 页面，签名校验不过。

**错误做法：**

```js
// ❌ 相对路径跳转会丢掉 token 段
location.href = '../other_page/index.html';
```

**正确做法：** 让服务端重新签一个针对目标页面的 token：

```js
async function fetchViewPath(pageName) {
  const r = await fetch(`./?page=${pageName}&_t=${currentToken}`);
  const j = await r.json();
  return j.url;   // 带新 token 的完整路径
}
```

### 12. 嵌入模型维度不匹配会静默失败

**报错：**

```
Unknown embedding_dimensions_mode: 'manual'
```

**原因：** 不同框架对这个字段的枚举值不一样。AstrBot 只接受 `auto` / `always` / `never`，填 `manual` 直接报错。

**而且更坑的是：** 维度不匹配（比如模型输出 1024 维，配置写 768）**不会报错**，只会让向量检索结果全是垃圾。上线前一定要拿一条已知数据验证召回。

---

### 13. 并发太高会让任务卡在「运行中」

**现象：** 批量给图片打标签，6 个任务永远停在 `status: running`。

**原因：** 并发 6 时，几个大文件（600KB~900KB 的 GIF）处理超时，异常没被捕获，状态没回写。

**解法：**

1. 并发降到 2~3
2. 给每个任务加超时保护
3. 启动时扫描并复位僵尸任务：

```python
# 启动时把 running 状态的复位成 pending
db.execute("UPDATE items SET status='pending' WHERE status='running'")
```

## 通用原则

**看到报错先排除自己的问题，再怀疑对方。**

这条吃过两次亏 —— 两次都是 JSON 传参被 shell 吃掉了引号，我却判定成「对方 API 有 bug」，白折腾半天。

**改完配置必须重启并验证。**

`systemctl reload nginx` 有时候不生效，行为没变就直接 `restart`。而且验证要用**真实客户端**，不能只看 `nginx -t` 通过。
